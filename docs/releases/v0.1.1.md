## Benchmarks and limitations

The recorded Windows synthetic cases use their pinned streaming candidate and baseline. They show substantially reduced peak working set for sparse short lines and a long nonmatching line. The long matching line took longer and used less memory. A live tree can change during a scan, dense output can require temporary disk, path sorting and rendered long lines need memory, and the binaries are unsigned.
